Лабораторная работа №1. 
Применение паттерна проектирования «Строитель» (Builder)

Тема :
Информационная система обеспечивает формирование отчета по лабораторным работам студента ИТ-специальности. Рассматриваются дисциплины «Базы данных», «Компьютерные сети», «Программирование». Отчет должен включать следующие разделы: титульный лист, цель работы, задание, теоретические сведения, описание экспериментальной установки, результаты работы, анализ результатов работы, выводы.
        Необходимо реализовать ввод данных и подготовку отчета в формате html с учетом особенностей дисциплины (наличие схем и других изображений )

1.Проблема :
Формирование таких отчётов вручную (например, в Word или Google Docs) занимает много времени, подвержено ошибкам, не обеспечивает единообразия оформления и не учитывает особенности каждой дисциплины:

Для «Программирования» нужно вставлять исходный код в специальном блоке.
Для «Баз данных» — добавлять схемы БД (изображения).
Для «Компьютерных сетей» — текстовое описание топологии или конфигурации

Паттерн Builder идеально подходит для случаев, когда:

Необходимо создать сложный объект, состоящий из множества частей (отчёт → титульник + цель + задание + ...).

Части объекта могут варьироваться в зависимости от контекста (дисциплина → разное оформление эксперимента).

Требуется разделить процесс конструирования от представления (алгоритм сборки ≠ способ оформления).

2.Решение, которое дал нам паттерн Builder

Разделение процесса сборки отчета на шаги.
Это решает проблему единообразия: отчет всегда имеет одинаковую структуру, но с адаптацией под дисциплину.В моей реализации паттерн применяется в классах ReportBuilder (абстрактный класс), HtmlReportBuilder (конкретный билдер для HTML) и ReportDirector_WithPattern (директор, управляющий порядком шагов).
Без паттерна вся логика была бы в одном большом методе с if-else, что усложняет расширение.

3.Вывод: Влияние внедрения паттерна на работу программы

Преимущества внедрения:

Гибкость: Легко добавить новую дисциплину (например, "Математика" — с формулами) или формат (PDF-билдер), не трогая GUI или директора.
Упрощение: Без паттерна if-else в одном методе растет, с паттерном — шаги изолированы, код чище.
Масштабируемость: Система готова к расширению (добавление изображений, кода) без риска ошибок.
Единообразие: Отчет всегда в HTML с единым стиле, но с особенностями (картинки/код) по дисциплине.

В итоге, паттерн Builder превратил ручное формирование отчета в автоматизированный процесс, где пользователь выбирает дисциплину в GUI, а система сама адаптирует контент. Это сэкономит время студентам и обеспечит профессиональный вид отчетов.
